# Public dish details (SK-0168)

`/menu/[dishSlug]` now reads the published Dish catalog detail projection. Draft, archived, deleted, malformed, and unknown slugs render the localized not-found page and are marked `noindex`. A published dish that is temporarily unavailable remains readable so a customer can see its information, but quantity and add-to-cart are disabled. The cart provider still revalidates price and availability when a customer adds an orderable dish; a stale page cannot bypass server rules.

The page follows the supplied `dish_details_ghormeh_sabzi` hierarchy: breadcrumbs, responsive gallery/thumbnails, purchase summary, ingredients, narrative content, related dishes, and blog stories. It also shows the current effective/base price and discount, preparation time, portion, allergen/dietary information, and specifications. Optional sections collapse when they have no public data. Related dishes must still be published and orderable; related blog posts must be published and past their publication time. Rich text is sanitized before rendering. Media are limited to ready images and their preferred processed variants; missing images use dimensioned placeholders.

The gallery uses named previous/next buttons, thumbnail buttons with pressed state, Left/Right keyboard navigation, intentional RTL mirroring, and a labelled full-screen dialog that closes with Escape. The purchase controls enforce the dish's maximum quantity and report cart success or failure without losing the page. All interface copy is translated for English, Portuguese, and Persian.

Product, MenuItem, and BreadcrumbList JSON-LD is validated and built from the same localized name, excerpt, evaluated price, orderability, and breadcrumb labels visible on the page. It does not reuse potentially stale SEO price inputs. The existing metadata service still supplies admin-managed title/social metadata. MongoDB detail projection was corrected to avoid selecting both the whole `ingredients` array and a nested ingredient path.

Next.js may send HTTP 200 when the not-found UI is streamed after headers, while adding `noindex` to the rendered result. The browser test checks the localized not-found UI, `noindex`, and absence of a purchase action; integration tests verify drafts and unknown slugs cannot be read from the catalog service. A hard HTTP 404 for all streamed requests would require a pre-stream existence check in the proxy and is not introduced here because it would add database work to every detail request.

Verification: unit, component, catalog integration, and browser tests cover structured data, content/price display, bounded cart quantity, keyboard gallery, and missing slugs. Final-content visual and performance audits remain in launch verification.

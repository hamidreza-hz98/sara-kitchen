# Cart step two

SK-0145 implements `/cart/address` as the pickup or delivery choice. A customer session is required before saved addresses or pickup confirmation can be persisted. After sign-in, the existing guest cart merges through the SK-0141 flow and the page refreshes the identity-scoped cart.

The step uses the shared address CRUD endpoints and `AddressEditor`, including Leaflet, keyboard-accessible fields, manual coordinates, and GeoJSON `[longitude, latitude]` storage. A new checkout address requires the customer to place or change the pin from its generic Porto starting position. Editing an address rechecks the cart afterward because the changed point can invalidate an existing delivery choice.

The cart stores an explicit `pickupConfirmed` flag or an owned `selectedAddressId`. No initial state counts as a fulfillment choice. Versioned `/api/cart` mutations accept only `{method:"pickup"}` or `{method:"delivery",addressId}`; client-provided fees and coordinates are rejected. The Carts service reloads the owned address through the Addresses module, evaluates the complete Porto municipal polygon, computes straight-line Haversine distance from the kitchen, and applies ascending server-owned distance bands. The normal price engine still grants free pickup and the existing €200 discounted-merchandise delivery waiver. An ineligible or removed address leaves the cart visible with invalid availability, no delivery fee, and no forward progression.

The boundary is the full 2,536-point Porto polygon in `src/server/modules/addresses/data/porto-boundary.json`, retrieved on 2026-10-14 from [GEO API PT's Porto municipality GeoJSON](https://json.geoapi.pt/municipio/porto). Its CAOP-derived geometry is held locally so checkout does not depend on a live geocoding service. Published Contact settings own kitchen coordinates and distance bands; the validated server environment and documented launch bands provide defaults until Contact settings are entered. The Contact settings editor provides numeric band controls and the server rejects unordered, negative, or excessive values.

The order summary is freshly calculated by the server. The continue control requires a nonempty, currently available cart and either confirmed pickup or a selected owned eligible address. `/cart/review` contains a guarded bridge for the next checkout task; it displays the current total but does not submit an order or take payment.

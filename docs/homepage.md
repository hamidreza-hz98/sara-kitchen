# Public homepage (SK-0166)

The homepage reads only the published Homepage settings revision. Its ordered references populate the hero slides, linked banners, up to six featured dishes, benefits, category banners, testimonials, and selected blog stories. The discounted section honors curated or automatic mode and the configured limit. Draft settings never appear. At render time, referenced categories and blogs must still be published; dishes must be published and currently available. Prices and active discounts come from the Dish pricing engine rather than settings or client input. A missing image causes only that image-dependent hero/banner to collapse; other sections remain available.

Each locale uses its configured text with canonical English fallback for missing item translations. A missing published Homepage revision produces a branded, localized hero and menu CTA without empty section headings. All other optional sections disappear when they have no public items. Admin-configured links follow the stored new-tab choice and use `noopener noreferrer` when opening another tab.

The content assembly is cached for 60 seconds and tagged with the Homepage settings item and catalog/category/blog lists. Mutations already invalidate these tags. Media URLs are signed for 15 minutes, so their lifetime exceeds the content cache window. Ready WebP display variants are preferred for the hero and banners; smaller ready WebP thumbnails are preferred for cards, with a processed JPEG/PNG fallback. Hero imagery is eager and high-priority; below-the-fold images are lazy, decoded asynchronously, and shown in dimensioned tiles to avoid layout shift. The only interactive client island is the hero selector; it has named buttons and an announced slide count, with no autoplay or timer.

The composition follows the supplied `layout/sara_kitchen_homepage` screen's hierarchy while using the approved theme and live configured content rather than the illustrative dishes and testimonials in the export. The `/menu`, `/blog`, and `/about` index pages belong to subsequent Phase 16 tasks; the homepage links target their agreed future routes. The current dish/category/blog detail routes are already present.

Verification: component tests cover missing sections, live-price presentation, hero navigation, and editorial links. The existing browser suite checks automated accessibility, streamed CSS ordering, hydration, and Emotion-rule uniqueness. Broader production performance budgets and cross-breakpoint visual audits remain in the launch verification phase.

The SK-0009 mobile LCP, image-byte, and Lighthouse thresholds still need measurement with final uploaded content on Portugal-region staging. Passing the build and local browser checks is not evidence that those production budgets have been met.

# Password hashing and production calibration (SK-0051)

Both administrator and customer credentials use the same server-only Argon2id implementation and a single parameter file, `src/server/security/password-policy.json`. The current profile is `m=19456` KiB (19 MiB), `t=2`, `p=1`, matching the [OWASP minimum recommendation](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). New passwords require at least 12 characters and at most 1024 UTF-8 bytes. Stored hashes include their parameters and a per-hash random salt. Plaintext is never a model field or repository argument.

After a correct password, the verifier compares stored parameters with the current profile using Argon2's `needsRehash`. If different, the Admins or Customers owner module replaces the digest with an atomic old-hash compare-and-swap. Failed passwords, disabled accounts, and concurrent password changes do not trigger a replacement or login success. The password version remains unchanged for a parameter-only rehash; actual password changes will increment it in the account-flow tasks. The raw password is never included in log calls, errors, database writes, or returned results.

## Benchmark evidence and release gate

Run `pnpm password:benchmark` on the production-equivalent Vercel Node.js Function runtime with the selected region, memory size, CPU allocation, and expected concurrency. The command performs one warm-up, 20 measured hash/verify pairs, and a four-hash concurrent sample. It prints only policy parameters, platform/CPU details, and timing statistics. For launch, record that runtime, p95 hash and verify latency, concurrency latency, function memory peak, and chosen profile here. Keep per-operation latency under one second, following OWASP's general guidance, while confirming login latency and denial-of-service limits under load. Increase work factors only if the production measurements support them; never go below the OWASP baseline.

Development-host measurement on 2026-09-16: Windows 10 build 26200, Node 24.15.0, Intel Core i7-1065G7, 20 measured samples after warm-up, with the current profile. Hash median/p95/max: 31/32/35 ms. Verify median/p95/max: 31/34/35 ms. Four concurrent hashes completed in 47 ms wall time. This is **not** a production benchmark and cannot close the production calibration gate. No Vercel project/runtime is provisioned in this repository yet. Repeat the benchmark there before production launch and update this record with results and any parameter change.

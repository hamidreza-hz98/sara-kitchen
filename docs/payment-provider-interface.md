# Payment-provider contract (SK-0149)

The Transactions module exposes `PaymentProvider` as the boundary to a gateway. Its `initiate` operation creates a provider-side attempt; `fetchStatus` is an authoritative status lookup; `cancel` and `refund` are explicit commands; `verifyWebhook` authenticates the **unparsed** body before any event mapping; and `mapEvent` converts verified provider data into the normalized SK-0148 transition input. A provider implementation must not mutate Orders or Transactions directly. The Orders-owned workflow persists the returned transition and order change atomically, while provider calls happen outside the MongoDB transaction.

The contract uses EUR integer cents, opaque provider payment/request IDs, normalized status and amount snapshots, safe response codes, and a required idempotency key for side-effecting calls. `payerMobile` is transient initiation input for MB Way and must not appear in provider status, logs, webhook results, or persistence. Provider implementations must validate their own real-gateway payloads and signatures. An invalid, stale, oversized, or malformed webhook yields `null`; mapping must never be called on unverified data. Unknown or ambiguous gateway results are reconciled through `fetchStatus`, not assumed successful.

`capabilities.cancel`, `.refund`, and `.webhook` declare supported operations. Methods still exist on every implementation; an unsupported command raises `PaymentProviderError("unsupported")`. The launch MB Way flow can set `refund: false` because refunds are handled by phone. A later PSP adapter may enable automated refunds without altering checkout's provider-neutral API. No live MB Way API, credential format, endpoint, or PSP-specific status mapping is asserted here; those belong to SK-0150.

`FakePaymentProvider` is a deterministic, in-memory **test fixture**, never a production payment rail. It has stable generated IDs and clock injection, simulates state transitions, signs a local HMAC webhook envelope, and exposes capabilities for testing. It does not persist the supplied mobile or make network calls. The reusable provider contract tests cover initiation and idempotent retry, status lookup, cancellation, refund totals or unsupported behavior, raw-body tampering, timestamp/signature rejection, and event mapping. Future gateway adapters must run the same contract suite plus their own provider-specific integration tests.

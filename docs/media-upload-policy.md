# Media upload policy (SK-0070)

This is the MVP admission policy for authenticated dashboard media uploads. Only an admin with the media-create permission may upload. The supplied Stitch media-management design shows an upload entry and translated metadata fields; it does not define security limits. Those limits are product decisions here.

| Format | Extensions      | MIME              | Maximum per file | Initial signature check            |
| ------ | --------------- | ----------------- | ---------------: | ---------------------------------- |
| JPEG   | `.jpg`, `.jpeg` | `image/jpeg`      |           10 MiB | JPEG SOI and EOI                   |
| PNG    | `.png`          | `image/png`       |           10 MiB | PNG magic bytes                    |
| WebP   | `.webp`         | `image/webp`      |           10 MiB | RIFF/WebP markers                  |
| AVIF   | `.avif`         | `image/avif`      |           10 MiB | ISO BMFF `ftyp` AVIF brand         |
| MP4    | `.mp4`          | `video/mp4`       |           50 MiB | ISO BMFF `ftyp` MP4 brand          |
| WebM   | `.webm`         | `video/webm`      |           50 MiB | EBML marker and WebM document type |
| PDF    | `.pdf`          | `application/pdf` |           15 MiB | PDF header and EOF marker          |

SVG, GIF, HEIC, MOV, audio, archives, HTML, scripts, and unknown formats are denied for launch. User-supplied MIME is checked but never trusted alone. The filename must be NFC-normalized, at most 180 UTF-8 bytes, and consist of a letter/number followed by letters, numbers, spaces, underscores, or hyphens and **one** final allowed extension. Thus double extensions, path separators, dotfiles, control characters, bidi overrides, `%`, trailing punctuation, and null bytes are rejected. Original names are display metadata only; object keys must be generated by the server and must not incorporate the submitted filename.

Maximum 10 files and 80 MiB total per request. An admin may upload at most 1 GiB of original bytes in a rolling 24-hour window; the active storage budget is 10 GiB including originals, variants, and in-flight reservations. The admission check fails closed if quota data is unavailable. The future upload service must reserve quotas atomically before storage, count the actual streamed bytes (not only `Blob.size` or `Content-Length`), release failed reservations, and enforce ingress/body limits upstream. These quotas are initial operational defaults and can be revised with measured usage.

Use the existing **private** `MINIO_BUCKET` for originals, variants, PDFs, and video. There is no anonymously readable bucket. A later delivery service may expose ready, non-deleted, approved public assets via an application-controlled URL or narrowly scoped short-lived signed URL; private files remain authorization-gated. Never serve raw unprocessed uploads directly, and do not let client input choose a bucket or key.

`inspectUpload` and `inspectUploadBatch` in `src/server/modules/media/validation/upload-policy.ts` implement admission checks against actual Blob slices. They are not a complete content-safety verdict: the later processing pipeline must fully decode/re-encode images, limit dimensions/pixel counts, inspect video/PDF with resource limits, scan for malware where available, and quarantine failures before publication. Signatures alone can be forged or form polyglots. PDFs should be served with download-safe headers rather than inline until a safe preview flow exists. No upload Route Handler is added in this task. For the initial Vercel deployment, the stricter [serverless processing policy](media-serverless-processing.md) permits only small images through a route; video/PDF and larger image processing await an approved worker.

This follows [OWASP's file-upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): extension allowlisting, content checks, generated storage names, size limits, authentication, private storage, and defense in depth.

# SK-0183 screen-reader audit

Audit date: 2026-10-17. Target: representative English, Portuguese, and Persian journeys with a desktop screen reader. This is an implementation and automated-semantics record, **not** a completed manual screen-reader sign-off.

| Flow           | Current accessible contract and evidence                                                                                                                                                                                                                                          | Remaining live check                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Cart           | Quantity controls name the dish; a polite live region now reports the dish and authoritative quantity or pending update. Loading is localized; price/availability errors are visible alerts. `cart-step-one.test.tsx` verifies names and announcement text.                       | With a real cart, verify add, quantity, remove, stale price, and error rollback are announced once and focus stays sensible.        |
| Validation     | MUI fields link error helper text to their inputs; address validation retains labelled coordinate inputs. Existing signup, address, and checkout tests exercise error text.                                                                                                       | Submit invalid forms with a screen reader and confirm first-error navigation and all field descriptions.                            |
| Dialogs        | Shared `AppDialog` labels itself by title and description. Confirmation starts on the safe cancel action. Admin and order-details component tests cover dialog name, focus, and confirmation.                                                                                     | Verify opening, Escape, focus trap, and focus restoration in a browser with a screen reader.                                        |
| Upload         | Each determinate progress bar has a file/overall label and numeric value. A per-file polite live region now announces stage changes without speaking every percentage point; errors use alerts and the final summary uses status. `media-upload-page.test.tsx` checks stage text. | Upload a mixed batch and confirm individual completion/failure and summary announcements are neither lost nor excessively repeated. |
| Charts         | Sales bars have a named list with one textual date/gross/refund/net entry per bucket; decorative bars are hidden. `dashboard-overview.test.tsx` verifies the text alternative.                                                                                                    | Confirm list navigation and value comprehension in NVDA/VoiceOver at desktop and mobile widths.                                     |
| Map            | The map region is named and now references the visible keyboard-alternative instructions. Latitude/longitude and postal/address fields remain usable without geolocation; map attribution is visible. `address-editor.test.tsx` checks the description and coordinate order.      | Confirm map controls do not trap keyboard focus and coordinate entry is understandable without sight.                               |
| Payment        | The verified payment state and guidance now occupy one atomic polite live region, so a pending-to-final transition is announced. The polling spinner is decorative. `payment-result.test.tsx` covers delayed success.                                                             | Drive pending, success, failure, expiry, and retry in a sandbox and check announcements.                                            |
| Order timeline | Dashboard and customer order histories are ordered lists with status, date/time, and relevant payment/actor information. `order-details.test.tsx` verifies timeline entries.                                                                                                      | Read a multi-event order in a screen reader and confirm chronological context and next actions.                                     |

Automated component tests, typecheck, locale-catalog consistency, and targeted lint passed for the changed surfaces. Automated DOM/ARIA checks establish that names and text alternatives are present; they cannot establish what a screen reader actually announces. NVDA is not installed on this workstation. The full database-backed cart/order and MB Way sandbox journeys are also not available in this environment (see `accessibility-audit.md`). Keep SK-0183 open until a human completes and records the live screen-reader checks above; remediate any findings and rerun the relevant tests.

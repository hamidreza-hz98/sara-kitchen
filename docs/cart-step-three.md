# Cart step three: order review

`/cart/review` shows the identity-scoped server cart, line totals, notes, pickup or owned delivery address, earliest ready time, and the server pricing breakdown. Its review endpoint is customer-only and `private, no-store`. Published, effective terms of service and privacy-policy versions are projected in the selected locale with English fallback; draft and future-effective policies are not accepted. The customer can read each policy in a sanitized dialog and must accept both separately.

MB Way is the only launch payment choice. The form validates a Portuguese MB Way mobile number (`+3519` followed by eight digits). The pay/place-order control requires a nonempty available cart, valid fulfillment, both published policies and explicit consent, MB Way selection and phone, and live provider capability. A fresh review preflight compares cart identity/version/total/fulfillment and policy IDs before any submission. Changes clear consent and require a new review.

The client holds an in-flight lock and reuses one browser-session idempotency key for a cart revision, including after a network interruption. This is a user-interface safeguard, **not** the durable idempotency guarantee: SK-0154 must atomically enforce it on the server with the existing Transactions module. The final order request carries the authoritative cart version, selected method/phone, and accepted policy IDs/versions; it never supplies a price.

As of SK-0146, the Order model, atomic checkout, and MB Way sandbox integration are not implemented (SK-0147–SK-0154). The review API therefore reports `submissionAvailable: false` and MB Way `enabled: false`; the button remains disabled. Direct `POST /api/checkout` fails closed with no order or payment write, including if a client bypasses the UI. This page must **not** be represented as a live ordering flow until Phase 14 replaces that boundary, persists policy consent with the order, and connects the payment-result route. The integration tests should then exercise duplicate requests and ambiguous provider timeouts against the real server operation.

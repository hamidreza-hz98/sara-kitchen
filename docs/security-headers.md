# Browser response security

Sara Kitchen applies one browser-security baseline to every App Router response through
`next.config.ts`. The policy is generated by `src/server/security/response-headers.ts`, so the
configuration and production-like tests exercise the same implementation.

## Header baseline

| Header                              | Production policy                                                            | Reason                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `Content-Security-Policy`           | Restrictive source allow-list; objects and embedding are disabled            | Limits content injection and browser access to external services         |
| `Strict-Transport-Security`         | `max-age=31536000; includeSubDomains`                                        | Makes browsers use HTTPS after the first secure response                 |
| `X-Frame-Options`                   | `DENY`                                                                       | Legacy clickjacking protection alongside `frame-ancestors 'none'`        |
| `X-Content-Type-Options`            | `nosniff`                                                                    | Prevents MIME-type guessing                                              |
| `Referrer-Policy`                   | `strict-origin-when-cross-origin`                                            | Keeps full paths on-site and limits cross-origin referrers to the origin |
| `Permissions-Policy`                | Sensitive capabilities disabled; first-party fullscreen and geolocation only | Minimizes ambient browser capability access                              |
| `X-DNS-Prefetch-Control`            | `off`                                                                        | Avoids speculative third-party DNS disclosure                            |
| `X-Permitted-Cross-Domain-Policies` | `none`                                                                       | Rejects legacy cross-domain policy files                                 |
| `X-XSS-Protection`                  | `0`                                                                          | Disables obsolete browser XSS filters that can create vulnerabilities    |

HSTS and `upgrade-insecure-requests` are production-only. HSTS deliberately omits `preload` until
every production subdomain has been inventoried and permanently committed to HTTPS. Development
keeps WebSocket and Next.js evaluation support and does not teach a browser an HSTS policy.

Next.js's identifying `X-Powered-By` header is disabled.

## Content Security Policy sources

Browser access is deliberately narrower than the set of server integrations:

| Capability                      | Allowed browser origin                                                                      | CSP directives                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Application assets and requests | `'self'`                                                                                    | default, scripts, styles, fonts, images, media, connections, workers, manifests, forms |
| OpenStreetMap tiles             | `https://tile.openstreetmap.org`                                                            | `img-src`                                                                              |
| OpenStreetMap embed             | `https://www.openstreetmap.org`                                                             | `frame-src`                                                                            |
| MinIO media                     | The exact origin derived from validated `MINIO_ENDPOINT`, `MINIO_PORT`, and `MINIO_USE_SSL` | `img-src`, `media-src`, `connect-src`                                                  |
| MB Way                          | None                                                                                        | Server-to-server only; redirects or a hosted SDK require a reviewed policy change      |
| Twilio and WhatsApp             | None                                                                                        | Server-to-server only                                                                  |

Wildcards, URL credentials, non-HTTP protocols, and non-loopback HTTP origins in production are
rejected while building the policy. Production deployments must therefore use an HTTPS MinIO
endpoint. Local production builds may use loopback HTTP solely for local verification.

The policy rejects plugins (`object-src 'none'`), inline event handlers (`script-src-attr 'none'`),
foreign form targets, and all framing of Sara Kitchen. It permits `data:` and `blob:` only for
images, and `blob:` only for media and workers.

The production `script-src` currently retains `'unsafe-inline'` because this App Router application
uses static rendering and Next.js emits inline bootstrap scripts. A request nonce would force every
page into dynamic rendering and remove CDN/static optimization. This exception is constrained to
first-party script origins, excludes `'unsafe-eval'`, and must be revisited before introducing any
third-party browser script. Emotion requires the matching inline-style exception.

## Cookies

Admin and customer credential cookies use the `__Host-` prefix in production and are `Secure`,
`HttpOnly`, `SameSite=Strict`, host-only, and scoped to `/`. The locale preference is not a
credential; it remains script-readable so the locale selector can persist a choice, but uses
`Secure` on HTTPS and `SameSite=Lax`.

## Verification

`tests/unit/security-headers.test.ts` constructs the production policy and verifies the complete
header baseline, exact external origins, development differences, rejected broad origins, and
credential-cookie flags. A release check should additionally start the production build and inspect
an actual response, because a hosting proxy or CDN can replace response headers.

When adding a browser-facing provider, add only its exact origin to the minimum required directive,
write a production-policy regression test, update this table, and retest the full payment or media
flow. Server-only providers must not be added to CSP.

# Order details dashboard (SK-0159)

`/dashboard/orders/[orderCode]` is a direct, shareable dashboard route. It validates the real order-code format and requires `orders:read` before loading an order; malformed and unknown codes produce the same not-found page. The server loads the order through the Orders module's safe projection. Customer/address snapshots and notes are present only for `orders:read-sensitive`. Transaction events are loaded through the Transactions module only for `transactions:read`, verified against the requested order ID, and projected to the fields needed by the UI; provider references and internal payment metadata are not passed as page props.

The page displays immutable checkout snapshots, status history, fulfillment timing, monetary breakdown, customer notes, and—where authorized—transaction history. Internal-note edits use the separate management revision. Fulfillment actions are offered only for the next locally eligible state and require confirmation; the existing server-side state machine, permission checks, payment checks, and optimistic revision remain authoritative. Cancellation follows its separate endpoint and warns about refund follow-up. A refresh after mutations prevents the page from treating its local state as financial truth.

The order-list summary and action menu link to full details. Labels are available in English, Portuguese, and Farsi. Component tests cover content, PII/transaction gating, and action confirmation; direct-page tests cover authorization order, code validation, missing orders, transaction permission, and cross-order transaction mismatch.
